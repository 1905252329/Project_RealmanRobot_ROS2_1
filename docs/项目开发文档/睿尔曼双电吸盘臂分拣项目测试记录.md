##### 规划器节点源文件

- [x] 从参数服务器中获取电吸盘的 IP 并传递给初始化电吸盘函数 initialize_gripper()

- [ ] 如果硬件初始化耗时很长，建议把它放在 action 开始前做一次热启动：将耗时的硬件初始化过程与动作执行分离的设计模式，确保动作响应的实时性。

  设计模式：将`initialize_rmRobot()`等硬件初始化逻辑移至专门的初始化阶段，使动作服务器专注于任务执行流程。

  1. **分层架构**：
     - 初始化层：处理硬件连接、资源加载、参数配置
     - 接口层：动作服务器/服务提供外部接口
     - 执行层：处理实时控制和任务执行
  2. **生命周期管理**：
     - 使用状态机管理组件生命周期(未配置→配置→激活→停用→清理)
     - 耗时初始化放在早期状态转换中
     - 动作执行仅在激活状态下进行
  3. **依赖注入**：
     - 执行组件通过接口获取已初始化的资源
     - 避免在动作处理函数中创建/初始化重量级对

- [ ] 保持原有定时器仅用于节点在无人发起 action 时的“**自主运行模式**”（如果需要），但在 action 执行时应暂停或禁止这些定时器以避免冲突（通过**标志**或**停止定时器**）
